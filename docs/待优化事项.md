| # | 事项 | 说明 |
|---|------|------|

| 2 | GitHub Trending / Papers with Code / GitHub Star AI 真机抓取 | 本机 TLS 证书吊销检查故障(`CRYPT_E_NO_REVOCATION_CHECK`,安全软件所致,当日早前 GitHub 曾成功);正常网络应自愈,代码有 fixture 测试 |

## 二、已裁决不做(YAGNI,评审确认)

| # | 事项 | 裁决理由 |
|---|------|---------|
| 1 | 压测/性能优化报告 | 个人工具,量级无需 |
| 2 | Redis(缓存/队列/限流) | 当前单机 + @Async 够用,需要时再引入 |
| 3 | SpringDoc OpenAPI | 可选;接口清单见本文档与 PROGRESS |
| 4 | Kubernetes / CI-CD 流水线 / 多实例 | 超出个人部署场景 |
| 5 | 会话搜索、收藏排序(置顶) | 收藏仅标记+筛选已满足 |
| 6 | 消息反馈训练回路/分析 | 反馈仅落库,无优化管线需求 |
| 7 | 新闻分页 | limit 200 + 前端筛选够用;量大再分页 |
| 8 | 主题跟随系统 / 多主题色板 | 亮暗双主题 + 手动切换已满足 |
| 9 | GSAP / TipTap / ECharts | 前端 spec 已裁决裁剪;纯 CSS 动效与 Naive UI 够用 |
| 10 | Quartz | `@Scheduled` cron 配置化等价满足 |

## 三、技术债与风险(已记录,择机处理)

| # | 事项 | 风险与建议 |
|---|------|-----------|
| 1 | **vector_store 无向量索引**(4096 维) | pgvector 0.8.x HNSW/IVFFlat 上限 2000 维;数据量大后检索全表扫描。方案:降维(1024/1536)或升级 pgvector/分段建索引;当前量级(<几千 chunk)无感 |
| 2 | HN 拉取串行 30 次请求 | 失效条目多时最坏 500 次串行;可并发拉取或换 Algolia API |
| 3 | 日报 AI 摘要失败无自动重试 | 失败保留 null,下次爬取会补(天然重试);可加单轮重试次数 |
| 4 | GitHub Search API 未认证限流(10 次/分钟) | 每日一次够用;高频场景需 token |
| 5 | 会话重命名/收藏无并发控制 | 单用户场景可忽略 |
| 6 | 模型仅 deepseek-v4-flash | 配置项已预留(`DEEPSEEK_MODEL`),需要时加 Pro 切换 |
| 7 | 前端轮询三 store 共用 composable 但语义各不同 | 已抽 `usePolling`;差异(自动停条件)在各自 refresh 内,可接受 |
| 8 | uploads 卷/文件无定期清理 | 已删除文档会删文件;孤儿文件可加巡检 |
| 9 | 备份仅文档化 | `pg_dump` 命令已写入部署文档;未做定时备份脚本 |

## 四、可选增强(低优先级)

1. **更多新闻源**:RSS 通用源(通用 fetcher 加 type=rss 分支)、中文源(阮一峰周刊)、Reddit/Dev.to API 类源
2. **日报**:AI 每周回顾(汇总一周新闻生成简报)、已读状态同步到收藏文档
3. **知识库**:文档重命名、目录树(文件夹)、分片级引用高亮定位到阅读器段落
4. **对话**:系统提示词自定义、会话导出
5. **运维**:健康检查页(/api/health 已有)、日志聚合、HTTPS 反代示例配置
6. **安全**:登录失败限流(需 Redis 或内存计数)、JWT 密钥轮换文档化(已有)
